## 关联 / 关系图 + links 同步(原 T5,2026-06-15 设计,已砍)

**当时做了什么:**
- 右栏「关联」标签:点击框后,右栏在「属性」「关联」间切换;「关联」打开 Obsidian **原生局部图谱**,显示该框的父子关系 + `for:` 映射。
- `src/core/links.ts` 的 `syncLinks()`:从框的父子关系 + `for:` 计算 `[[链接]]`,写进 frontmatter 的 `links` 数组(单向:子→父、子→for-goal,避免循环)。
- 面板内还有一个 `drawRelations()`:在右栏列出该框的父/子,可点跳转。

**为什么砍:**
- 收敛裁定:**关系 = 层级嵌套**,不再用 `for:` 显式链接(嵌套本身就编码服务关系)。`for:`/coverage 整片删除,links 的计算来源也就没了一半。
- 原生图谱无法嵌进面板 DOM(Obsidian 私有 API),只能弹独立 leaf,体验割裂。
- "结构预览"也一并砍(见 handoff #C/#E):一棵可编辑树足够,不画第二棵。

**复活路径(若将来要):**
1. `links` 改成**纯从嵌套派生**(子→父),不再依赖 `for:`(已无此字段)。
2. `syncLinks()` 在插件 `refresh()` 后、CLI 写操作(dispatch/stamp/createBox)后调用;注意 links 写身份文件需在可写集内或无活派活时。
3. `drawRelations()` = 右栏一个只读列表(父 + 子 + 反向引用),点击跳转——这是当时 cuca 觉得"做得挺好"的那块,比原生图谱更实用,优先考虑这个而非图谱。
4. 原生局部图谱当**可选增强**,不是主路径。

**注:** 这套代码当时只在未提交工作树里,**git 历史无法捞回**,要重做得照本图纸重写。
